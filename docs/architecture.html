组件拓扑

三个容器一个 DB,加上若干被装机的物理节点。所有 API 流量经 Backend。

当前现状 NOW

  • Frontend :3000 — Vite/React SPA;开发时 dev server,prod 用 nginx
  • Backend :8000 — Go 单体 binary;启动时自动 apply migrations
  • PXE-services :host network — dnsmasq + TFTP + iPXE,2s 轮询 .reload 文件 HUP dnsmasq
  • Postgres :5432 — 单实例;7 个 migration 已 apply 到 v6
  • 共享卷:/etc/dnsmasq.d(backend 写 → pxe 读)、/tftpboot(双向)

建议演进 NEXT

  • Backend 单实例 — 多实例会写同一 dnsmasq config 互相覆盖,需要引入 leader-election 或外置生成器
  • Postgres 无 replica,无 PITR — 装机平台数据可重建,但 audit log 历史值得至少 daily backup
  • PXE-services 跑 host network → 不能在云端跑(host network 需要专用网卡或裸机)

失败模式 WATCH

  • Backend 挂 → PXE token 颁发不动 → 装机停;dnsmasq 旧配置仍生效,已开机的机器不受影响
  • dnsmasq 挂 → 新机器拿不到 IP/boot file → 装机停
  • Postgres 挂 → backend health/ready 返 503,整体 down

PXE 装机时序

5 条 swimlane:Node / dnsmasq / Backend / DB / Mirror。从机器上电到 status=active 全程。

关键路径 NOW

  • Boot script 阶段:backend 颁发一次性 PXE token(默认 4h TTL = INSTALL_TIMEOUT × 2)
  • Preseed 阶段:token 验证不消费(installer 可重试)
  • PostInstall 阶段:token 验证 + 消费 + 绑 client IP
  • callback 失败 5 次 × 10s 重试,失败保留脚本下次开机再试
  • 装机超时 120 min(env INSTALL_TIMEOUT_MINUTES)→ 后台 watcher 自动标 error

失败模式 WATCH

  • Mirror 不可达 → kernel/initrd 下载失败 → iPXE shell;backend 不知道
  • TPM enroll 失败 → 装出来仍能 boot 但每次开机要密码;日志在 /var/log/osbaka-tpm-setup.log
  • callback 5 次全失败 → 节点卡 installing → 120min 后 error;脚本仍在盘,reboot 还会试

建议演进 NEXT

  • PostInstall callback 改成 progress-aware:支持 {"step":"luks_done"} 等多步上报
  • Backend 加 health endpoint 给 PXE-services 用,避免 backend 重启时丢 token

节点状态机

7 状态。所有转换由 SetNodeStatus() 校验。非法跃迁返回 ErrIllegalTransition。

触发因子 NOW

  • operator — UI/API 显式操作(蓝边)
  • system — postinstall callback / background watcher(橙边)
  • auto-discover — 未知 MAC 触发 PXE(绿边)

关键不变量 NOW

  • discovered → 操作员审批 → pending|installing(防共享 L2 自动装机)
  • installing 进入时自动打 installing_started_at;离开时清
  • heartbeat 只允许 active ⇄ offline;其他状态心跳只更新指标

建议演进 NEXT

  • 加 decommissioned 状态做软退役 — 当前 delete 立即销毁审计 snapshot 已经在 audit 里,但 hostname/MAC 回收需要更明确
  • error 状态加 error_reason 字段 — 当前看不出是装机超时、网络失败还是 TPM 失败

后台 watcher / 调度器

三个长期运行的 goroutine,在 main.go 启动时拉起。

当前现状 NOW

  • StaleNodeChecker — 5min ticker,扫 active 节点 last_heartbeat 超 10 min → offline
  • InstallTimeoutChecker — 同 ticker,扫 installing 节点 installing_started_at 超 120 min → error
  • DnsmasqScheduler — leading + trailing coalesce;N 次 ScheduleRegen 收敛到 ≤ 2 次执行;200ms cooldown;LastError 暴露到 dashboard

建议演进 NEXT

  • 三个 ticker 合一 — 当前都是 5min 同步,可以共用 ticker 减少 goroutine
  • 引入 backoff:同节点反复装机失败,timeout watcher 重复标 error 没有指数退避,操作员 UI 上看不到"已经第 3 次失败了"
  • 把这三个 watcher 暴露 prometheus metrics:run_count / error_count / last_run_age

节点注册流

从 UI 创建一个新节点到 dnsmasq 实际加进 reservation 的完整路径。

关键步骤 NOW

  • POST /api/v1/nodes 入口校验:hostname/MAC/IP/mirror/disk path
  • passphrase + IPMI password 在写 DB 前 AES-256-GCM 加密(FIELD_ENCRYPTION_KEY)
  • DHCP reservation 同步插入,操作员 unseen
  • ScheduleDnsmasqRegen() 非阻塞,scheduler 合并 burst

建议演进 NEXT

  • CSV 批量导入当前是前端逐条 POST — 加 POST /api/v1/nodes/bulk 后端原子事务,减 N 次网络 + N 次 audit row
  • UI 增加 dry-run mode:校验所有字段但不持久化,让用户在大批量导入前确认
